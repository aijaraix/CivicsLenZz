# EVIDENCE AND PROVENANCE RULES — Cryptographic Preservation

In CivicLenZ, an uncorroborated assertion is not a fact. Evidence must be captured, hashed, and archived at the moment of discovery.

---

## 1. Capture and Archival Doctrine

1. **Direct TLS HTTP Capture**:
   * All raw payloads (HTML pages, JSON responses, PDF dockets) are captured via direct HTTP requests over TLS.
   * Captured payloads are written to `data/snapshots/` as unmodified byte files.
2. **SHA-256 Byte Verification**:
   * The SHA-256 hash must be computed directly over the raw captured byte stream before any text encoding or DOM parsing:
     $$\text{ContentHash} = \text{SHA256}(\text{RawBytes})$$
   * This hash acts as an immutable digital seal against subsequent modification or silent web page changes.
3. **Retrieval Metadata Standard**:
   Every harvested record must record:
   - `source_url`: Full canonical deep link
   - `retrieved_at`: ISO 8601 UTC timestamp
   - `http_status`: Actual response code (e.g., 200)
   - `content_type`: Mime type reported by origin server
   - `byte_length`: Exact byte count of the raw response payload
   - `content_hash`: Hexadecimal SHA-256 digest
   - `raw_object_reference`: Relative path to preserved byte snapshot

---

## 2. LLM and Search Output Prohibitions

* **Search Results are NOT Evidence**: Search engine snippets (Google, DuckDuckGo, Bing) do not constitute evidence. They are pointers to discovery.
* **LLM Inferences are NOT Proof**: Text generated by Gemini or other LLMs without an attached byte-hashed source document is rejected at the canonical boundary.
* **No Speculative Provenance**: Provenance fields must document actual network transport, never synthetic attribution.
